Introduction
Purpose
This Software Requirements Specification and Design document is to outline the software requirements for the "Mini Supermarket App" project. This document provides a detailed technical foundation for the deployment, development, and operation of the mobile and web application on various platforms. It serves as a comprehensive guide for developers to plan, assign tasks, and implement the application. Additionally, testers will utilize this document to design test cases that align with the specified requirements, ensuring the final product meets quality standards and user expectations.
 Scope
This document covers the Mini Supermarket Application, which is part of the broader initiative to digitize supermarket operations and enhance the shopping experience through online and mobile solutions. The application allows customers to browse and purchase products conveniently, while enabling managers and staff to efficiently manage orders, products, and customer feedback.

Intended Audiences and Document Organization
This document is intended for:
Development Team: Responsible for developing detailed design, implementing, and performing unit tests, integration tests, and system tests for the application.


Database Team: Responsible for designing and maintaining the database structure and ensuring data consistency across modules.


Documentation Team: Responsible for writing the User Guide and technical documentation for the application.


UAT Team: Responsible for conducting user acceptance testing sessions with end users to ensure that the application meets business and user requirements.

Below are main sections of the document:
1. Introduction: This section describes the general introduction of this  document.
2. Functional Requirements: This section describes the functional requirements in detail.
3. Non-functional Requirements: This section describes the non-functional requirements of this application such as user access and security, interfaces, screens, and performance.
4. Other Requirements: This section describes other requirements such as archive or security audit function.
5. Appendixes: This section describes other requirements for this application and other supporting information for this document.
NOTE: Please refer to section 6.1 for all acronyms and abbreviations you may encounter within this document.

Use Case Description

Name
Restock Goods
Description
This use case allows the manager to restock goods.
Actor
Manager/Warehouse staff
Trigger
When the manager clicks on the [Restock] button in the Goods Management view.
Pre-condition
Manager’s device must be connected to the internet.
Manager is signed in with their account.
Post-condition




Sequence Flow

Activities Flow

Business Rules

Activity
BR Code
Description
(3)
BR22
Input Data Rules:
Manager must provide all required information in the "Restock product" form:
1. Product: Must select an existing product from the dropdown list.
2. Quantity to Add: Must be a positive integer.
3. Barcode/SKU: System automatically fetches or validates against the PRODUCT table.
(4)
BR23
Capacity Validation Rules:
The system calculates: TotalStock = CurrentStock + ImportQuantity.
The TotalStock must be checked against the MaxStock constraint in the PRODUCT table.
• If TotalStock > MaxStock, system moves to step (4.1) to display Error MSG 9 (e.g., "Quantity exceeds warehouse capacity").
• Else, the process continues to step (4.2).
(4.2), (5)
BR24
Submission Rules:
Manager clicks "Restock" button to confirm or "Cancel" to abort.
• If "Cancel" is clicked, system discards changes and returns to the Goods Management main screen.
• If "Restock" is clicked, system calls method CreateImportRequest() and moves to step (5) to process data.
(6)
BR25
Data Integrity Rules:
The system validates data consistency in the database:
• If data is invalid (e.g., Product ID no longer exists or Database connection lost), system moves to step (6.1) to display Error MSG 10.
• If valid, system executes method StoreData() to update the PRODUCT table and log the transaction into IMPORT_HISTORY.

Activity

Selecting Rules:

(3)
BR27
Input Validation Rules (Pre-check):
Manager enters "Quantity to Export". The system performs an immediate check:

• Else, the input is temporarily accepted.
(3.1)
BR28
Confirmation Rules:
Manager clicks the corresponding button to process:
• If Manager clicks "Cancel", the system clears the form and returns to the main Goods Management screen.
• If Manager clicks "Export" (Save to confirm), the system proceeds to step (4) to call method ProcessExportRequest().
(5)
BR29
Data Consistency Rules:
Before storing, the system re-validates the data against the PRODUCT table to ensure no changes occurred during the session (e.g., another user exported the same item).
• If data is Invalid, move to step (5.1) and display error notification (MSG 10).
• If data is Valid, move to step (5.2) to execute StoreData() and update inventory.
(6)
BR30
Execution & Display Rules:
Upon successful data storage, the system must:
1. Deduct the exported quantity from the Product collection: NewStock = OldStock - ExportQuantity.
2. Log the transaction details (including the optional Note from the UI) into the EXPORT_HISTORY table.
3. Display a success notification (MSG 7) and refresh the datagrid with the updated goods list.

Technical Concern
Low Growth Rate: If the growth rate of the application’s user base or data volume is low, there is less risk of performance issues. However, it’s important to plan for potential future growth to ensure the application can scale effectively.
Large Data Volume: A huge amount of data can lead to saving/loading issues. It can slow down database queries and increase the load time of pages. Efficient data management strategies and optimization of database queries can help mitigate these issues.
Excessive Content on a Single Page: Too much content on a single page can lead to longer load times and a less responsive user interface. Implementing pagination or infinite scrolling can help manage the amount of content displayed at once.
High Traffic: If the application experiences high levels of traffic, it could strain the server and lead to slower response times. Implementing load balancing and caching strategies can help manage high traffic.
Security Measures: While necessary, certain security measures can impact performance. For example, data encryption and decryption can be resource intensive. It’s important to implement security measures in a way that balances safety and performance.
